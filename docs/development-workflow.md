# 開発ルール(イシュー・ブランチ・PR)

このプロジェクトでの、作業の進め方のルールです。Claude Code 向けの指示は、[CLAUDE.md](../CLAUDE.md) にあり、内容は同じです。

## 1. ワークフロー

```
イシュー作成 → ブランチ作成 → 実装 → コミット → プルリクエスト作成 → マージ
```

| 手順 | やること | コマンドの例 |
|---|---|---|
| 1 | **イシュー作成**。作業の前に、必ず用意する。まず既存のイシューを確認し、なければ作る | `gh issue list` → `gh issue create` |
| 2 | `main` を最新にして、ブランチを作る | `git switch main` → `git pull --ff-only` → `git switch -c feature/#12-task-api` |
| 3 | 実装する(ビルド・動作の確認を含む) | `cd backend && ./gradlew compileJava` |
| 4 | 内容ごとに、日本語のメッセージでコミットする | `git add` → `git commit` |
| 5 | **プルリクエスト作成**(本文に `Closes #12`)。プッシュしてから作る | `git push -u origin <ブランチ名>` → `gh pr create` |
| 6 | 内容を確認して、マージする。マージ後に、ローカルを後片付けする | GitHub の画面、または `gh pr merge` → `git switch main` → `git pull --ff-only` → `git branch -d <ブランチ名>` |

**すべての作業で、この流れを守ります**(誤字の修正も含みます)。

- **イシューの作成は必須です。** 作業の開始前に、GitHub のイシューを作成します。同じ内容のイシューがすでにあるときは、それを使います。
- **`main` への直接プッシュは、禁止です。**
- **プルリクエストの作成は、必須です。** `main` への変更は、プルリクエスト経由のみです。

## 2. ブランチ名

形式: **`種類/#イシュー番号-短い説明`**

| 種類 | 使う場面 | 例 |
|---|---|---|
| `feature` | 機能の追加 | `feature/#12-task-api` |
| `fix` | 不具合の修正 | `fix/#15-column-delete` |
| `docs` | 文書の更新 | `docs/#20-readme` |
| `chore` | 設定・環境などの雑務 | `chore/#7-dev-workflow-rules` |
| `refactor` | 動きを変えない整理 | `refactor/#30-rename-entity` |

短い説明の部分は、半角の小文字・数字・ハイフンだけを使います。

※ `#` は、URL では特別な意味を持つ記号です。URL に書くときは、`%23` にします(GitHub の画面では、自動で変換されます)。

## 3. コミットメッセージ

- **日本語で書きます。**
- 1 行目に、「何をしたか」を、簡潔に書きます(例: `Task エンティティと V2 マイグレーションを追加`)。
- 理由や補足が必要なときは、1 行空けて、本文に書きます。
- 1 つのコミットには、1 つの目的の変更だけを入れます。

## 4. main ブランチの保護

GitHub の設定で、`main` を保護します。

- `main` へ、直接プッシュすることはできません(**管理者を含め、全員**)。必ず PR を経由します。
- PR の承認(レビュー)は、必須にしていません(1 人で開発しているため)。自分の PR は、自分でマージできます。
- 強制プッシュと、`main` の削除はできません。
- PR のマージ後は、ブランチが、自動で削除されます。

## 5. PR を作る前の確認

- ほかに開いている PR と、変更するファイルが重なっていないか。重なると、片方をマージした後に、競合(同じ場所を別々に変更したことによる衝突)が起きます。
- ビルドが通るか。データベースに関わる変更は、起動して、確認する。
- Flyway のマイグレーションは、適用済みのファイルを書き換えず、新しい番号のファイルで追加する。

## 6. 設計に関わる作業

API の仕様、データベースの設計、画面との連携などは、実装の前に、方針を決めます(Claude Code では、プランモード)。
要件定義書(`docs/requirements/`)と食い違うときは、先に、確認します。

## 7. ルールを守らせる仕組み

| 層 | 内容 | 強さ |
|---|---|---|
| GitHub の設定 | `main` のブランチ保護 | サーバーが拒否する。回避できない |
| Claude Code のフック | `.claude/hooks/guard-git.js`。`main` へのコミット・プッシュと、形式に合わないブランチ名を、実行前に止める | Claude Code の操作を、強制的に止める |
| Claude Code の設定 | `.claude/settings.json` の拒否リスト | 危険なコマンドを、止める |
| 指示 | [CLAUDE.md](../CLAUDE.md) | 毎回読み込まれる指示。強制力はない |

## 8. 緊急時

`main` へ直接プッシュする必要があるとき(通常は、ありません)は、GitHub のリポジトリの Settings → Branches で、保護を一時的に外し、作業後に、必ず元に戻します。
